# Dynamic scan pool: desktop behavior and native port

The desktop screenshot shows three different counts: the full candidate pool, the symbols eligible for the current market scan, and the number already analyzed in this cycle. They must remain separate in the native Radar. The current Apple app can request one manually selected Finnhub symbol or that symbol plus up to four saved watchlist symbols. Its watchlist is not a dynamic discovery pool, and requested subscriptions are not a count of analyzed symbols.

## Desktop reference

1. `WallstreetOnlineRankingPages` defines 18 ranking pages across top performers, flops, most traded, gaps, reversals, high range, and regional indices. The example [Top Aktien Performance](https://www.wallstreet-online.de/statistik/top-aktien-performance) ranks price performance; [Top Handelsvolumen](https://www.wallstreet-online.de/statistik/top-aktien-meistgehandelt) is the distinct turnover ranking. A performance list must not be labelled a liquidity list.
2. `WallstreetOnlineMarketDataClient.loadRankings()` fetches the pages with bounded concurrency and interleaves their first 50 rows. The public performance page has separate rankings for 1 day, 7 days, 30 days, and 1 year, plus an index filter with a dedicated DAX page. `WallstreetOnlineDiscoveryService` subsequently selects at most 40 unique instrument paths for ticker resolution across categories. That desktop resolution budget is not a page-row limit. It caches successful discovery for 30 minutes; a failed refresh retains the previous snapshot and retries after five minutes. Morning DAX ranking population still needs a time-specific source check before it can drive scan eligibility.
3. `MainController` joins the weekly universe with wallstreetONLINE discovery. `DynamicMarketUniverse` combines those discovered symbols with a configured core and pinned watchlist. It scores discovery rank and observed activity, caps each US/European region at 200 symbols, and limits replacements to five per refresh. Its selection snapshot lasts 30 minutes.
4. `ScanCycleCoordinator` filters the pool for currently active markets, orders the eligible symbols, requests provider data, updates live source telemetry, and reports completed/eligible/pool counts. The ranking pages only select candidates; they do not themselves provide a live executable quote or minute-bar stream.

The old code paths are `market-data/.../WallstreetOnlineRanking.kt`, `WallstreetOnlineMarketDataClient.kt`, `app/.../company/WallstreetOnlineDiscoveryService.kt`, `app/.../scanner/DynamicMarketUniverse.kt`, and `app/.../ui/ScanCycleCoordinator.kt`. Treat these as behavioral references, not as code to copy wholesale into SwiftUI.

## Native implementation sequence

The native project now has a provider-independent `DiscoveryCandidate` with source identity, category, rank, observation time, optional ranking origin, and optional provider symbol plus exchange MIC and currency. `DiscoveryRankingPage` lists the aggregate performance page plus the requested DAX, CDAX, MDAX, TecDAX, SDAX, Eurozone 50, US 30, US Tech 100, US 500, and Trending Stocks paths. The index performance pages use day, week, month, and year rankings; Trending Stocks uses a separate activity ranking based on relative volume. `DiscoveryRankingBatch` validates at most 50 rows per table; `DiscoveryRankingAssembler` merges available batches and reports empty tables explicitly, preserving daily rank priority when the same instrument appears more than once. `DiscoveryCandidateSelector` interleaves categories and deduplicates stable instrument IDs. Its 2,000-row input bound is a defensive data limit, not a target pool size or scan budget.

`MiminaviInfo1Source` now fetches the user's JSON endpoint while Radar is active. Its decoder accepts only the aggregate page attribution and four expected periods, validates the generation age, the HTTPS instrument URLs, prices, percentages, ranks, and response size, then maps distinct instrument paths into discovery candidates. The source panel reports current, saved, or unavailable status and candidate count. Its candidate list shows the JSON company names, ranks, periods, paths, and a local search without treating a name as a provider ticker. Older saved snapshots without names remain readable. Freshness uses both fetch time and the JSON generation time, so a recently fetched old ranking is not labelled current. `DiscoveryRefreshCache` refreshes about every 30 minutes, retries failures after five minutes, and retains the last good snapshot; scene inactivity cancels an in-flight refresh without imposing the failure backoff. `DiscoverySnapshotStore` keeps a versioned local snapshot. The JSON contains website paths rather than verified market-feed symbols, so none of these candidates is subscribed to Finnhub or scanned. The ten requested index and activity pages are catalogued but are not present in this endpoint; an empty morning DAX table cannot yet be tested through it.

Radar shows a transient activity banner while fetching the ranking, preparing the Finnhub feed, or sending its symbol subscriptions. It reports the saved candidate count or requested symbol count where available. The current native feed has no bounded scan cycle or provider acknowledgment count, so the banner uses an indeterminate progress indicator rather than an invented percentage. The ranking decoder accepts stock detail paths with or without an `-aktie` suffix; both variants occur in the live JSON.

1. Define a provider-independent candidate record with a stable instrument identifier, source category, rank, observation time, and optional resolved ticker. Keep source parsing, ticker resolution, pool selection, quote collection, and signal detection in separate services. Reject unresolved or ambiguous names instead of guessing a ticker.
2. Extend the bounded JSON discovery adapter with separately identified index and activity feeds as they become available. Keep fixture tests for each feed shape, foreground-only fetching, 30-minute caching, last-good retention, and failure backoff. Preserve per-page and per-period availability, including an empty morning ranking. Deduplicate instruments across rankings and verify their exchange/currency before scanning.
3. Merge discovered symbols with user-pinned symbols and a stable core. Bound the total pool, per-source work, provider subscriptions, and replacements per refresh. Persist the last successful pool and its provenance locally; never mistake an old snapshot for live source health.
4. Add a market-hours and provider-capability gate, then a foreground multi-symbol scan coordinator. Keep source coverage, pool size, eligible count, processed count, last successful refresh, and errors as separate telemetry. Stop all network work when the scene becomes inactive or enters the background.
5. Port live source panels and selected-signal chart behavior. Show each source only when its adapter actually runs. Validate signal semantics against desktop fixtures and fresh device runs before calling the Radar equivalent to the prototype.

The bounded Finnhub Watchlist feed is insufficient for this pool: a public ranking page returns company names and website instrument paths, while a market feed needs exact provider symbols, exchange coverage, subscription capacity, and minute history. The watchlist path assumes user-entered provider tickers and excludes names needing resolution; it does not prove that the account receives trades for every requested ticker. The Apple app must validate ranking mappings and account limits before subscribing to discovered symbols. The desktop's Yahoo, Tradegate, and Euronext paths do not become available merely by saving their keys or URLs.

## Distribution boundary

The miminavi.tech endpoint identifies wallstreetONLINE as its underlying ranking source. Routing through the user's JSON does not itself establish redistribution or App Store display rights. [wallstreetONLINE's disclaimer](https://www.wallstreet-online.de/disclaimer) requires editorial permission to include its content in commercial databases. Resolve the intended use and data rights before distribution; confirm the quote provider's display and redistribution rights too. The current wallstreetONLINE page notes delayed exchange prices; do not present its ranking price as a live quote. Keep the discovery adapter replaceable so a licensed feed can supply the same candidate model.
